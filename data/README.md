* **Источник:** Roboflow Universe (проект `construction-site-safety`).
* **Ссылка:** https://universe.roboflow.com/roboflow-universe-projects/construction-site-safety/dataset/28
* **Версия:** v28.
* **Автор (Workspace):** roboflow-universe-projects.
* **Лицензия:** CC BY 4.0 (разрешено использование, модификация и распространение с указанием авторства).
* **Дата получения:** 1 февраля 2023 г. (дата выгрузки Roboflow).
* **Способ получения:** Выгрузка с Kaggle (датасет `snehilsanyal/construction-site-safety-image-dataset-roboflow`). В репозиторий изображения не включены (согласно правилам), для воспроизведения необходимо скачать их по ссылке и распаковать в папку `data/`.

## 2. Схема разметки и словарь классов
Формат разметки: **YOLO (YOLOv8)**. 
Каждому изображению соответствует `.txt` файл. Строка разметки имеет вид: `class_id x_center y_center width height`, где координаты нормированы в диапазоне `[0, 1]`.

**Словарь классов (10):**
0. `Hardhat` — Каска (положительный класс СИЗ).
1. `Mask` — Медицинская маска (положительный класс СИЗ).
2. `NO-Hardhat` — Голова без каски (**отдельный объект с рамкой**).
3. `NO-Mask` — Лицо без маски (**отдельный объект с рамкой**).
4. `NO-Safety Vest` — Человек без сигнального жилета (**отдельный объект с рамкой**).
5. `Person` — Человек (полный силуэт).
6. `Safety Cone` — Дорожный конус.
7. `Safety Vest` — Сигнальный жилет (положительный класс СИЗ).
8. `machinery` — Строительная техника (экскаваторы, погрузчики).
9. `vehicle` — Транспортные средства (грузовики, самосвалы).

**Важное правило разметки:** 
Классы `NO-*` являются **отдельными объектами с рамкой** (например, рамка вокруг головы без каски), а не отсутствием положительного объекта. Для детекции это означает, что модель ищет визуальный паттерн «голова без каски», а не просто «отсутствие каски».

## 3. Разбиение выборки (Data Splitting)
Исходное разбиение Roboflow (train 2605 / valid 114 / test 82) было случайным и содержало **утечку данных** (кадры из одного видео попадали в разные выборки).

Для исправления был написан скрипт `resplit_data.py`, который выполняет **групповое разбиение** (Group Split). Кадры группируются по префиксам имен файлов (сцены/видео), и целые группы распределяются по выборкам.

* **Итоговое разбиение:** 
  * `train` — 1453 изображения (51.9%)
  * `val` — 795 изображений (28.4%)
  * `test` — 553 изображения (19.7%)
* **Тестовая выборка** заморожена до момента выбора финальной конфигурации (E2). Оценка на тесте проводилась один раз после завершения обучения.

## 4. Контроль качества и проверки
В файле `test_basic.py` реализованы минимальные тесты:
1. Проверка существования путей к изображениям (YAML).
2. Проверка координат в `[0, 1]` и номеров классов в `[0, 9]`.
3. Проверка контрольных хэшей (MD5) — пересечений между выборками нет.
4. Проверка визуализатора (размер изображения не меняется).
5. Проверка схемы вывода модели.

Утечка групп проверяется скриптом `check_leakage.py`. В исходных данных найдено 31 пересечение, в новом разбиении — 0.

## 5. Ограничения и риски
1. **Сдвиг домена (Domain Shift):** Датасет собран из разных источников (YouTube-видео, другие датасеты Roboflow). Разные камеры, ракурсы и освещение.
2. **Шумовые изображения:** В датасете присутствуют нерелевантные кадры (интерьеры офисов, книжные магазины, младенец, гоночные болиды). Это создает шум и потенциальные ложноположительные срабатывания.
3. **Mosaic-аугментация:** В версии v28 Roboflow применил склейку 4 картинок в одну (сетка 2х2). Это затрудняет визуальный анализ и создает артефакты на границах.
4. **Постановочные кадры:** Часть кадров снята в постановочных условиях (люди позируют), что снижает реалистичность.
5. **Неоднородность разметки:** Разные источники могут иметь разные правила обводки частично перекрытых объектов.

## 6. Использование
Детектор не может быть единственным механизмом допуска к опасной работе. Ошибки зависят от камеры, перекрытия и освещения. Критические решения требуют человеческого контроля. Правило отказа (fallback): при уверенности модели ниже 0.6 для критичных СИЗ кадр передается оператору.
